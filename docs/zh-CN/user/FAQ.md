# 常见问题

**这个仓库和 npm 官方源是什么关系？**

不冲突。这里发布的包都在自己独立的 `@ohos-npm-ports/*` scope 下，是原包的一份带鸿蒙适配的重打包版本，不会覆盖或影响原包在 npm 上的正常安装。用不用完全是消费方自己的选择（见 [usage.md](usage.md) 的 alias/overrides 用法）。

**为什么不直接给上游提 PR，让官方支持鸿蒙？**

能直接提 PR 的都应该优先提 PR——这是维护成本最低、用户体验最好的路径，本仓库自己的贡献指南也这么要求（见 [contributing.md](../contributor/contributing.md) 的准入规则）。这里收录的是「暂时没能合入官方、但业界确实有使用诉求」的包：可能是上游还没回应，可能是改动涉及的平台判断上游暂时不愿意合并。一旦上游收口，本仓库对应的包就会被移除（见「项目治理」）。

**这些包安全吗？会不会被恶意篡改？**

移植时不允许改动原作者信息和开源许可证（见贡献指南），改动范围限定在鸿蒙平台适配相关的部分（loader 分支、二进制签名、依赖版本），源码可审计。CI 会跑构建和基本的加载验证（见 [../contributor/verification.md](../contributor/verification.md)），但容器验证不能代替真机场景下的完整验证——生产环境部署前建议自行验证。

**为什么我装的版本号带一个奇怪的后缀（比如 `5.1.7-8`）？**

这是本仓库自己的修订号，格式是 `<上游版本>-<修订号>`。上游版本不变、只是移植补丁本身有改进时，修订号会往上加；这样能在不跟上游版本号冲突的前提下持续修 bug。

**为什么 `optionalDependencies` 里有一堆我从没主动装过的包？**

那些是平台专属子包（比如 `xxx-openharmony-arm64`），是给对应主包在鸿蒙平台上自动选用的二进制槽位，正常现象，不需要手动干预。

**这个包能在 HarmonyOS（商用发行版）上用吗，还是只能用在 OpenHarmony 社区版？**

大多数情况下两边都能用——本仓库主要针对社区版 OpenHarmony 构建，但构建出来的产物通常也能在 HarmonyOS 上正常加载。如果遇到某个包只在其中一边工作，欢迎提 issue。

**我想贡献一个新包，应该看哪份文档？**

从 [contributing.md](../contributor/contributing.md) 开始；不确定该走哪种移植手法先看 [porting-guide.md](../contributor/porting-guide.md)；具体的目录/命名/版本规范在 [port-spec.md](../contributor/port-spec.md)。

**我在用的包貌似坏了，该怎么反馈？**

提 issue，附上：包名与版本、复现步骤、报错信息、你的鸿蒙系统版本。维护者或社区贡献者会跟进；如果你已经定位到问题所在，也欢迎直接提 PR 修复。
